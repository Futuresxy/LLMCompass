面向多精度部署组合的 Tensor Core 算力配比探索

在固定 M/N 网格上，通过扩展点积单元的 K 并行度，比较 1:2:4、1:2:6、1:2:8、1:4:8。先完成可复现的计算建模，再用真实 PPA、供数约束和跨模型验证决定芯片配比。

研究问题：在规定的芯片预算与质量要求下，哪种多精度算力配比能在一个预先定义的模型部署组合上，获得更好的吞吐、延迟或能效，同时控制未参与设计的模型与高精度负载的退化？

1. 故事应当围绕部署组合与硬件预算展开

算力配比是硬件资源分配问题。传统位宽递减所对应的峰值增长规律，不自动等于现代推理部署的最佳资源分配。提出更高的低精度算力后，需要证明新增面积和功耗在多种负载上值得投入。

只保持核数与频率不变，再观察 FP4 GEMM 变快，会得到较容易预期的结果。能够支持芯片决策的结论应进一步比较：同样的额外面积，用于低精度 K 扩展、增加常规计算引擎、增加操作数带宽，哪一种在目标部署组合中更有价值。

通用性来自通用 GEMM 接口、保留高精度功能、一个冻结的硬件选择，以及跨模型家族和运行条件的验证。无需要求模型内部混合使用三种精度；单个模型的 GEMM 可以统一使用一种格式，整个部署组合仍可能同时包含 BF16、MXFP8 与 FP4 模型。

需要接受的边界：增加 FP4 算力无法直接加速统一 BF16 GEMM；保持核数时它可能没有性能变化，固定芯片面积时还可能因核数减少而变慢。应当量化这种代价，不能用“所有模型都会受益”作为研究前提。

2. 统一 GEMM 精度与混合精度的区别

本轮的“统一精度”指一份负载中的 GEMM 都使用同一种 A/B 格式，累加使用 FP32。Softmax、归一化、路由、通信等可以保持它们需要的格式与测量时间。输入实验入口的非 GEMM 时间固定，不随低精度峰值自动缩短。

比较固定项改变项能归因于什么
配比实验模型、格式、精度校验、batch、上下文、核数与频率1:2:4 → 1:2:8 等计算资源分配及其实现代价
格式实验模型、质量门槛、硬件BF16 → MXFP8 / NVFP4 等量化、存储和计算格式的共同影响
预算实验总芯片面积或功耗、HBM/IO 条件、质量门槛配比、核数、必要的存储组织芯片设计选择的实际价值

同一配比实验中，不能把基准 FP4 与新设计 FP4 的权重存储量再缩小一次。两者已有相同数据格式，新增压缩收益为零。W4A16 解量化到 FP16 的路径也不能直接记为原生 FP4 GEMM。

3. 格式与三档计算能力的表示

格式payload本参考设计的计算档位默认存储描述
FP16 / BF1616 bit16 bit无共享 scale
MXFP88 bit8/6 bit32 元素 + 8 bit scale
MXFP66 bit8/6 bit32 元素 + 8 bit scale；紧凑 6-bit packing
MXFP44 bit4 bit32 元素 + 8 bit scale
NVFP44 bit4 bit16 元素 + 8 bit scale，另加每 tensor 的 FP32 scale
HiF44 bit4 bit64 元素 + 32 bit 分层元数据

MXFP6 的不同编码保留名称，但在该参考设计中共享计算档位。三种 4-bit 格式也共享配置的峰值；这是一项候选硬件能力假设，不能据此认为现有任意 GPU/NPU 都原生支持所有格式，或它们的数值误差、功耗和访存相同。

存储计数会按分组轴补齐整个 block。A 的分组沿 K；数学形状为 [K,N] 的 B 也沿 K 分组，因此使用第二倒数轴。它们不能都机械地按最后一维分组。宏 word 对齐、swizzle、复本和 scale 重读需要由后续局部存储后端补充。

格式依据：CUTLASS scaled operands、PTX block-scaled MMA、NVIDIA NVFP4 说明、HiF4 原始论文。这里实现描述和成本计数，没有实现数值量化器或低精度 GPU 算子。

4. K 扩展如何进入 SCALE-Sim

配比16-bit L8/6-bit L4-bit LM/N 网格
1:2:4163264固定 R×C
1:2:6163296固定 R×C
1:2:81632128固定 R×C
1:4:81664128固定 R×C

对于 D=A×B，每个 PE 的一次更新计算 L 个标量乘积并更新 FP32 部分和。将原 K 转成 Q=ceil(K/L) 个向量 token；SCALE-Sim 的 OS 单元对每个 token 执行一次点积更新。A/B 的 token 分别沿行/列传播，保留原有 skew 和排空时隙。

原问题：M × N × K
点积模式：R × C 个 PE，每个 PE 每个阵列 step 处理 L 个乘积
SCALE-Sim 计算拓扑：M_tile × N_tile × ceil(K/L)
峰值：R × C × L MAC/step
最后一组：只记录真实 K 的有效 MAC，其余为尾部空槽

这是对点积阵列的一种计算抽象：它要求点积结果/累加更新以及 PE 链路能按一个 step 工作，操作数和 scale 已就绪。L 从 64 增大到 96/128 后能否保持相同频率和更新速率，需要综合或实测数据支撑。当前没有将更长归约树的代价凭空设为已验证事实。

当前后端只支持该 OS 映射。WS/IS 会改变空间维度和驻留位置，不能简单把 K 压缩后沿用同一解释；代码对此显式报错。SCALE-Sim 使用已安装、已验证的 2.0.2 计算组件，没有修改第三方源码，也没有把依赖升级为 v3。

5. 周期、尾块与多引擎调度

一个任务覆盖至多 R×C 的输出，沿完整 K 归约。多个独立任务按波次分配到芯片上的计算引擎；批量 GEMM 保持独立输出，不能拼接 K 后假装得到同一个问题。

读取 SCALE-Sim demand matrix 的行数作为包含首拍的已分配时隙，不把最后一个从零开始的 timestamp 当作周期数。对于该版本、一个输出 tile，分配时隙为 Q+R+C−2；真实结果由组件生成，并不直接使用这个公式代替调用。

单个 16×16 网格，FP4E64E128含义
K=409664+30=94 拍32+30=62 拍1.516×，填充/排空没有减半
K=161+30=31 拍1+30=31 拍没有收益；新增点积槽无法被填满
K=193，E963 组、最后 1 个有效元素；K packing=193/288保留真实 MAC 数，不把 padding 算成有用工作

利用率分别报告 K packing、M/N 空间填充、波次填充和流水线效率。整机有效利用率为有效 MAC/(所有引擎峰值×计算周期)，避免把只观察忙引擎得到的高利用率当作整个芯片的利用率。

7. SRAM：本轮的精确范围与下一步衔接

本轮输出的是计算时间线和向量 token 数，token 既不是 SRAM 地址，也不是一次完整 SRAM word 事务。尚未由源数据、广播寄存器、collector、bank 和端口仲裁还原实际供数，所以不会声称已经得到真实 L0 每拍读取或硬件可行性。

算子入口还给出 max(计算调度时间，HBM/L2 必需传输时间) 的理想重叠估计。必需字节计入 A/B 数据和元数据、D 写回；默认 β=0，不读初始 C。它没有计入跨 tile 重复搬运、局部供数、转换或量化计算，不是实测 kernel 延迟。

下一阶段在同一 profile 下接入：操作数载入与驻留规则 → 每拍请求 → bank/端口仲裁 → 数据就绪 → 阵列推进。复用寄存器能否摊薄 SRAM 带宽，需要通过加载截止时间、寄存器容量与缓冲槽判断。

存储实验保持/改变必须报告
现有 SRAM容量、bank、lane、端口都保持新增计算后产生多少阻塞；原带宽余量能支撑哪些模式
联合升级在固定总容量下搜索宏组织为达到供数要求增加多少面积、动态能耗、泄漏和互连成本
完整预算把新增 TC+SRAM+RF+控制放回芯片预算核数/频率是否改变，以及全芯片结果

已有 cost_model/cacti.py、local_sram.py 可复用宏成本查询；当前 dot_product_sram.py 的结构化访问假设不能自动视为本后端的已验证物理访存。两者尚未闭环。

10. 避免专用设计：预先冻结的实验矩阵

维度建议覆盖要防止的偏差
模型结构Dense GQA、不同 Attention 结构、MoE；同家族不同规模仅换同一模型的 hidden size 不能证明跨家族通用性
运行阶段Prefill、decode、批处理 decode、专家小 batch只挑大 GEMM，遗漏内存受限和利用率低的场景
长度/batch短/长上下文，batch=1 与服务目标范围内的 batch用大 batch 的收益代表低延迟部署
格式BF16 控制组、MXFP8/6、至少两种 4-bit 格式；每次配比比较固定格式把量化收益混进硬件收益，或忽略元数据差异
形状长/短 K，M 很小、N 很大，K=96/128 边界和尾数，真实非对齐维度只选被新点积长度整除的尺寸
质量每个模型/格式独立量化与质量评估；固定可接受门槛性能模拟器不能证明所有算子都可无损转成 FP4
选型/验证按模型家族分组，预留整个家族和未见 batch/长度；选型后冻结设计根据测试集反复选择配比，造成数据泄漏

当前配置中的 design/holdout 字段与统计入口已经实现，但示例留出集仍是形状代理。正式研究需要替换为真实模型轨迹，记录框架、kernel、量化配置、形状分布和哈希；不能把 112 组示例描述成 112 个真实模型实验。

部署组合的权重应来自事先给定的部署目标或明确的等权规则。建议同时报告按工作负载等权的几何平均、最差加速比、退化比例、各模型/阶段明细，并补充不同合理权重下的敏感性。不要让一个有大量重复形状的模型在统计中自动获得更高权重。

12. 固定芯片预算下的公平比较

A_core(design) = A_other_core + n_TC × A_TC(design)
                 + A_operand_storage(design) + A_added_interconnect(design)
N_core(design) = floor((A_die_budget - A_fixed_IO) / A_core(design))

上式只是预算组织方式：必须使用互不重复的面积范围，原 core 中已包含的 SRAM/RF 不应再次计费。减少核数后，向量、寄存器、局部 SRAM、调度等资源也可能一起减少；不能只把 TC 数乘一个面积比例而保留其他核心资源不变。

固定功耗实验需要活动率、泄漏、存储/互连、频率电压等信息。当前提供的 TC 相对功耗只覆盖其中一部分。应先报告固定核数的增量成本，再补全全芯片成本，避免把 TC 面积效率当作全芯片效率。

一个更完整的对照是：给传统配比相同的新增面积，允许它选择增加计算或带宽；然后比较统一低精度模型和 BF16 控制负载。若 1:2:8 仅在理想供数且不计面积的条件下领先，应该将其判为条件性收益。

P1：目标芯片校准用现有 H100/B200/B300 与 Ascend 平台验证对应原生模式。计算饱和、带宽饱和、小形状、访存计数的分离微基准；按形状保留验证集。
P2：设计研究接入真实 PPA 和真实模型；冻结组合权重及候选选择，再运行留出集。等预算对照、退化约束、Pareto 与敏感性；自定义配比需综合/RTL/单元数据支撑。

现有芯片只能校准其实际支持的模式和对应层次，无法直接证明未制造的 1:2:6 设计。不要用一个全局拟合因子补偿所有形状与格式；应分开校准计算更新、填充排空、存储、转换和启动，并检查设计排序是否在误差范围内稳定。

本报告对应一个可运行的参考计算模型和研究实施方案。相对 PPA 待输入；示例结果不是量化精度验证、GPU/NPU 性能实测或全芯片最优配比结论。
